Factory Inventory Management System

Architecture overview: a Vue 3 single-page application backed by a FastAPI service that serves in-memory data loaded from JSON files. There is no database.

Data Flow

Request path

  1. Filter change. A user selects Time Period, Warehouse, Category or Order Status. The choice is stored in the shared useFilters singleton.
  2. API call. A view calls api.js with getCurrentFilters(). Values of all are dropped, and the rest become query params.
  3. Routing. FastAPI matches the route and validates the query params.
  4. Filtering. apply_filters and filter_by_month filter the in-memory lists. Quarters such as Q1-2025 expand to three months.
  5. Validation. Results pass through Pydantic response_model and are returned as JSON.
  6. Render. The view stores raw data in refs. Computed properties derive totals, charts and tables.

Observed Gaps

Client calls endpoints the server does not define. client/src/api.js calls /api/tasks (GET, POST, PATCH, DELETE) and /api/purchase-orders (POST, GET by backlog item), but server/main.py has no matching routes. It does define PurchaseOrder models and loads purchase_orders.json, which /api/backlog uses to set has_purchase_order. Task and purchase-order features will fail against the current backend until those routes are added.
